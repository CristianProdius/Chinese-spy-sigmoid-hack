I read all four files and probed `analyze.py` with a small in-memory trace: three runs, r2 is the wrong one. I edited nothing in your folders; the one temp file I made is deleted.

**Analyzer gaps, most dangerous first**
1. **Run labels are ignored unless they're in a `feedback`-type event or in prose.** In the probe, it missed both `flagged: true` on r2's response and `runs_summary: [{run_id:"r2", outcome:"incorrect"}]`, so the verdict came from a majority vote. Fix: add `--incorrect RUN` and read each label dict as a whole (a run/event id plus a negative value in one dict).
2. **Any `SIGMOID_` string can win, not just `source_id` values.** In the probe, a tool_call_id (`SIGMOID_CALL_R2`) ranked #2 with 40 points. Fix: when a `source_id` key exists, only print ANSWER from values under that exact key.
3. **Nothing writes `answer.txt`.** ANSWER only prints to the terminal, so hidden or look-alike characters depend on copy-paste. Fix: add `--answer answer.txt` that writes the raw string plus `\n` and prints its hex.
4. **A UTF-8 BOM crashes the load** (confirmed). Fix: `encoding="utf-8-sig"`.
5. **Item times without an offset are read as UTC**, so the Angola timezone trap (WAT, UTC+1) slips. A notice saying `valid_until 18:00` in local time is treated as 19:00 local, so it still looks valid for an hour after it expired. Fix: check those fields as both UTC and UTC+1, and flag the item if either reading has expired.
6. **Dropped items are only caught by the key name around the id.** Events of type `context_evicted`, fields like `included/used/selected: false` and `status: "dropped"` are all ignored. When the request lists no ids, the analyzer falls back to matching content or event order, and then an evicted decoy counts as reaching the model. Fix: treat those as dropped for that run.
7. **Every id list inside the model request counts as reaching the model**, including `candidates`, `retrieved` and `considered`. Fix: when the request has several lists, keep only included/used/selected/context.
8. **The −30 "also in correct runs" penalty hits the real culprit when the newer notice was evicted.** Every run had the stale notice and only the wrong run lost the newer one. The procedure's set difference (r1 Step 5) is then empty, and it doesn't say what to do next. Fix: if the wrong run's inputs are a subset of the correct runs' inputs, rank by which item supplies the wrong claims and read the "missing here" list.
9. **The final request is the last `model_request` by array position.** Event types like `model_request_retry` are classified as control events, so a retried final request is skipped. A culprit one step further back (a summary or memory rewrite in an earlier request) is also invisible. Fix: count retry types as requests, and trace back through earlier requests when the final request holds items with no `SIGMOID_` id.
10. **Timeouts and cache TTLs are never checked.** It doesn't compare elapsed time against `timeout_ms`, doesn't flag result `status: timeout|error|fallback`, and ignores `cached_at` + TTL. A 2-hour-old cache hit with a 15-minute TTL passes, because staleness is a flat 12 hours. Fix: add those three checks.
11. **The bad-status check matches "test" inside "latest"** (confirmed), which puts a strong false flag on the newest notice. Fix: `\btest\b`.
12. **Leaks from another run are only caught through tool-call ids.** An item carrying `payload.run_id` or `origin_run` of a different run isn't flagged. Fix: flag any nested run id that belongs to another run.
13. **The wrong-place check reads places from every prompt event.** It switches off if a system prompt lists several zones, or if the user's question only appears inside the model request. Fix: take places from the user's question only.
14. **Tool arguments aren't compared across runs**, for example `area: "Kilamba Kiaxi"` only in the wrong run. Arguments are also stripped from item text. Fix: diff tool_call arguments per run and flag the matching result.
15. **The past-deadline rule labels runs before the majority vote** and can mark a correct run wrong ("cut until 12:00, now restored"). Fix: skip sentences that also say supply is restored or normal.
16. **Smaller ones:** the injection check fires on normal correction wording ("overrides the earlier notice"). A final answer that cites a decoy id gives that id +10. A model request with inline `result`/`output` keys is treated as holding its own response, so that text is left out of the content match.
